# Zeer Prep: first historical snapshot round-trip

Executed 2026-10-13. **PASS for the bounded first engine slice.** This is a
correctness and operability result, not a comparative performance leaderboard.

## Implemented behavior

The Rust importer reads a bounded lightwalletd-compatible range, checks the
network and predecessor/end anchors before and after capture, validates linked
heights, and writes an immutable local segment. The store checks its manifest,
segment checksum and individual records before serving. The separate native
gRPC API serves bounded batches and requires the snapshot's dataset ID on every
range request. `prep inspect` verifies a closed/reopened snapshot.

The initial attempted legacy endpoint `mainnet.lightwalletd.com:9067` did not
resolve. The working endpoint was discovered in the current Zingolib README.
There was no TLS bypass. Python reference capture and Rust import use separate
decoders but the same provider. They do not establish independent full-node
consensus, canonical-chain completeness or wallet compatibility. Provider
version strings are self-reported. Prep stores represented compact data without
viewing keys, note decryption or plaintext memos.

## Validation

- Rust 1.99.0 on Linux x86_64, dependencies fixed by `Cargo.lock`.
- **24 passing tests:** 17 store tests and 7 integration tests. The importer
  integration test also exercises multiple rejection cases: gaps, truncation,
  changed terminal anchor, wrong network, broken parents, extra blocks,
  oversized blocks and a stalled stream.
- Store tests cover corruption, no-clobber publication, incomplete writes,
  bounds, snapshot identity and independent range cursors.
- Native gRPC tests cover multiple clients, nonempty Sapling/Orchard fields,
  batch byte limits, unread-response admission, cancellation and bounded shutdown.
- `cargo fmt --all -- --check`, `cargo clippy --workspace --all-targets --locked
  -- -D warnings`, and `cargo build -p prep --locked` passed.
- Independent review found and prompted fixes for response-stream permit
  lifetime, shutdown grace time, height overflow and publication-error wording.

## Timing observations, not a speedup claim

Each local smoke used one warmup and five sequential reads of the same 256
blocks in eight batches. The first smoke's median was 17.400 ms; the repeated
smoke after restart was 29.380 ms. Both used an **unoptimized dev build** and
included Python decoding/normalization and cursor checks, with reference
equality outside the timer. The variability is retained, not filtered away.

The reference provider was accessed over the internet; Prep served its prepared
snapshot locally. Do not divide these timings to advertise a speedup. No
equivalent local competitor run, ingestion-throughput experiment, cold-cache
isolation, client-language comparison or CPU/RAM consumption trace was performed.

## Resources and operational outcome

Build, source capture and serving checks ran in separate phases on the shared
VPS. Build was capped at 3 CPU / 4 GiB; server and verifier each at 1 CPU /
512 MiB. The experiment used an internal Docker network with **no published
ports**. The server had a read-only root filesystem and snapshot mount.

All Prep containers stopped at completion; the server exited cleanly with no
OOM flag. Previously checked application services remained active. The work
directory, including Cargo cache/target, used 966,305,024 bytes; an additional
pinned Rust image was retained. Combined experiment usage remained under the
authorized 40 GiB operational envelope. No billing changes or unrelated data
cleanup occurred.
